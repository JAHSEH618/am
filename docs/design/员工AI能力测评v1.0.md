# 员工 AI 能力测评 · 汇报材料

## 一、目的与边界

在管理者视角下，按时间窗对每位员工"用 AI 协作的方式与产出"形成一份能力洞察报告，辅助识别：真正高产的人、需要培训的人、有协作风险信号的人，以及团队协作的空白方向。

边界：

- 不是绩效打分系统，不替代 code review 与 1-on-1；
- 不向员工公开个人指标，避免行为对抗；
- 不存代码内容（Git 侧只采元数据），员工端采集对话流水是为了评判员工的协作方式，不是评判 AI；
- 不分岗位，相对化基线是窗口内全员的 P25 / P50 / P75，任务难度差异由大模型评分做归一化。

> 系统不替管理者下结论，给出的是**异常信号 + 典型会话样本**，由人解读决策。

---

## 二、采集范围

- **员工端会话**：完整对话正文、会话过程、工具调用、token；
- **日聚合**：协作时长、消息量、首响时延、卡壳重试、Top 模型；
- **Git 提交**：仅元数据（时间、作者、说明、增删行数、分支）+ AI 协助判定；
- **大模型双判**：难度、完成结果、五维能力、协作模式四项评判结果；
- **员工 / 项目主数据**：用于归属与展示。

---

## 三、计算

三层流水线：

- **日**：按人按日聚合协作时长、会话 / 消息 / 工具、token、首响与重试、当日 AI 协助提交、Top 模型；
- **会话**：对窗口内需审计的会话给出难度、完成结果、五维能力、协作模式四项评判；
- **窗口**：合并日数据、会话审计与 Git，产出团队页与个人明细。

**生成方式**：管理员选时间窗（默认本自然周）→ 点击「生成」→ 异步执行 → 完成后展示。同窗口已生成过直接走缓存；跨窗口仅补审新增会话；强制刷新会忽略缓存重跑；生成失败可重试。

**会话双判**：两套独立大模型按同一评分细则打分，再做一致性过滤：

- 难度 1～5：两路分差 ≤ 1 采信；
- 完成结果（三态）、协作模式（五类）：两路必须完全相同；
- 五维能力（各 1～5）：每维分差 ≤ 1 采信。

不一致样本仍写入，纳入窗口聚合时**权重 × 0.3**。评分细则显式禁止以礼貌 / 长度 / 中英文 / 工作时段加分。

**窗口报告**：

- 团队页展示各维度分布与 P 分位基线，供个人对照与 Watchlist 阈值使用；
- 个人页在会话审计分数上做难度加权 → 与 Git 指标合成综合三档 → 给出典型会话供下钻读原文；
- 小样本保护：窗口内会话 < 30 或活跃天 < 5 → 不出该员工详细画像，仅列基本量，且不参与团队分位计算。

---

## 四、测评维度

> 维度 1 为客观计量；维度 2～5 来自会话双判；维度 6 用 Git 交叉验证；维度 7 为加权后的相对位置；维度 8 为规则触发的辅助信号。

---

### 维度 1 · 投入与产出

仅做客观统计，不区分优劣：

- 协作时长（窗口内会话活跃时间的区间并集，单日 ≤24h）；
- 会话条数、消息量、token；
- AI 协助提交次数与新增行数；
- 习惯分布：常用模型、常用工具、常用项目。

---

### 维度 2 · 任务难度

会话级难度 1～5：

- **1 · 极易**：拼写 / 格式订正、简单事实查询；
- **2 · 简单**：单文件单函数改动、知识问答、命令查询；
- **3 · 中等**：多文件改动、调试、需要理解项目上下文；
- **4 · 困难**：架构调整、性能优化、复杂调试、跨模块；
- **5 · 专家**：系统设计、难复现 bug、新技术调研、大重构。

窗口聚合时给出难度分布、平均难度、高难度（≥ 4）占比。

---

### 维度 3 · 完成结果

三态判定：

- **完成**：用户接受结果或明确表示问题解决；
- **部分**：改换思路、仍在迭代但未明确放弃；
- **放弃**：会话挂起、显式放弃或长时间无回应。

**加权完成率**避免「只做简单题」拉高数字：

```
加权完成率 = Σ (难度 d 上的完成率 × 权重_d) / Σ 权重_d
权重：1 → 1，2 → 2，3 → 4，4 → 8，5 → 16
```

---

### 维度 4 · 协作能力五维

每维 1～5 分（信息不足时给中位 3）：

- **需求拆解**：把复杂问题拆为可执行小步；
- **上下文管理**：提供足够代码 / 错误 / 约束让 AI 理解任务；
- **调试能力**：定位问题、读错误、设计验证；
- **工具编排**：合适工具 + 适时切换；
- **自我纠错**：发现 AI 跑偏时调整方向，而非死磕。

按难度加权后输出个人雷达，并叠加团队 P50 基线。

---

### 维度 5 · 协作模式

会话级单选，描述「怎么用 AI」，与维度 4 互补：

- **杠杆型**：用 AI 加速明确任务，会话短、结果明确、有产出落地；
- **学习型**：新领域探索、概念解释、教程式问答；
- **探索型**：开放式 brainstorm、架构讨论、选型对比；
- **调试型**：「粘错误 → 试方案 → 粘新错误」的循环为主；
- **依赖型**：基础问题反复问、缺乏自主判断、卡壳反复。

窗口聚合时给出团队 / 个人各模式占比。

---

### 维度 6 · 代码侧验证（Git 三角）

防止「会话里看起来好、代码没跟上」：

- **每小时 AI 协助提交** = AI 协助提交 ÷ 协作小时，看单位时间产出；
- **每千 token 落地行数** = AI 协助新增行 ÷ token × 1000，「聊得多落地少」会很低；
- **7 天回滚率** = 7 日内被 revert / hotfix / bugfix 的占比，质量信号；
- **高难度提交占比** = 关联难度 ≥ 4 会话的提交 ÷ 总 AI 协助提交，看能否落地难事。

AI 协助判定：提交时间 ±30min 内同员工 / 仓库有重叠会话即认定为 AI 协助，并附置信度；置信度过低在前端打"疑似"标签。

---

### 维度 7 · 综合相对位置

按以下权重将三项合成内部得分，**对外仅展示三档**：

```
综合分 = 0.40 × 加权完成率
       + 0.30 × 五维均值 / 5
       + 0.30 × 每小时 AI 协助提交（团队百分位）
```

输出 **前 25% / 中 50% / 后 25%**，不展示绝对分；数据不足者不参与分位计算。

---

### 维度 8 · 关注清单（Watchlist）

窗口内满足阈值即标记，作为约谈核实线索而非结论，区分负面信号与正面信号。

负面信号：

- **高投入低产出**：协作时长 ≥ P75 且 每小时 AI 协助提交 ≤ P25 → 1-on-1 了解任务难度 / 是否卡死；
- **高回滚率**：AI 协助提交 ≥ 5 且 7 天回滚率 > 25% → 加 code review 强度；
- **难度结构偏低**：会话 ≥ 30 且 难度 1～2 占比 > 80% → 任务分配复盘；
- **依赖型偏高**：会话 ≥ 30 且 依赖型占比 > 35% → 关心 + 任务难度复盘；
- **完成率偏低**：会话 ≥ 30 且 完成率 ≤ 团队 P10 → 主动了解。

正面信号：

- **沉默 + 产出常**：会话 ≤ P10 且 AI 协助提交 ≥ 3 且 每小时提交 ≥ P50 → 邀请做内部 AI 协作分享。

每位员工最多挂 **6 条典型会话**，覆盖「高难度完成」「高能力体现」「高难度放弃」三类，点击下钻可读原文。

---

## 五、使用纪律

**明确不进入指标体系的伪信号**：

- 对话礼貌 / 措辞、提问字数 / 会话长度、中 / 英文使用、工作时段 / 周末活跃、模型偏好 —— 均与能力无关，不评判；
- 工具调用次数本身 —— 看用对没用对，不看用多少；
- 单次会话的"成败" —— 单点高方差，必须窗口聚合；
- Token 消耗量本身 —— 必须配产出口径才有意义。

**出报告前的自查清单**：

- 时间窗 ≥ 7 天；
- 窗口内活跃员工 ≥ 10；
- 双判一致样本占比 ≥ 70%；
- 已有 Git 提交侧数据；
- 不会把这份报告对外公开或截图传播；
- Watchlist 上的人，结合 1-on-1 解读，不直接据此做决策。

任一项不通过，**不出此报告**或不基于此报告做行动。

---

## 六、未解决与风险

- **行为对抗**：员工知道有审计后行为会变形，靠"不公开个人指标"压制，做不到根除。
- **大模型评分偏置**：模型对自己擅长领域可能低估难度，靠双模型分别擅长不同领域 + 不一致样本人工抽查缓解。
- **AI 协助判定误判**：基于时间窗口的推断必有假阳性 / 假阴性，置信度低时前端打"疑似"标签。
- **隐私边界**：使用细节会暴露员工行为节奏，上线前需与法务 / HRBP 对齐边界。
